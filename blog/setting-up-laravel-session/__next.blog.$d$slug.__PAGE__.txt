3:T173c,<h3>Session-based Authentication in Laravel</h3>
<p><strong>What is session-based authentication?</strong></p>
<p>Session-based authentication is created on the server for each user after they login. The server then sends a unique session identifier for the client side to store which is usually stored in the cookie. This cookie is used for subsequent requests to authenticate the user.</p>
<p><strong>What is a cookie?</strong></p>
<p>It is a small piece of data that a web sever sends to a user&#39;s web browser which is then stored and is sent back with every subsequent request to the same server. Think of it as a way for websites to remember users across different sessions.</p>
<h3>Setting up Session-based Authentication in Laravel</h3>
<p>Setting up API Authentication in Laravel is simple since they already have the starter kits. You can also check their <a href="https://laravel.com/docs/11.x/starter-kits#breeze-and-next">documentation</a> for more information.</p>
<p><strong>SPA Authentication</strong></p>
<p>This is from their documentation. You can read more from <a href="https://laravel.com/docs/11.x/sanctum#spa-authentication">here</a></p>
<blockquote>
<p>For this feature, Sanctum does not use tokens of any kind. Instead, Sanctum uses Laravel&#39;s built-in cookie based session authentication services. This approach to authentication provides the benefits of CSRF protection, session authentication, as well as protects against leakage of the authentication credentials via XSS.</p>
</blockquote>
<blockquote>
<p>In order to authenticate, your SPA and API must share the same top-level domain. However, they may be placed on different subdomains. Additionally, you should ensure that you send the <code>Accept: application/json</code> header and either the <code>Referer</code> or <code>Origin</code> header with your request.</p>
</blockquote>
<h4>Steps:</h4>
<ol>
<li>Run the <code>php artisan breeze:install</code> command and select the API stack as the desired stack.</li>
<li>Run the <code>php artisan migrate</code> to run the newly created migrations.</li>
<li>Ensure this environmental variables exist in your <code>.env</code> file</li>
</ol>
<pre><code class="language-php">FRONTEND_URL= //Add your frontend url
SESSION_DOMAIN=.localhost //with a dot before the localhost
SANCTUM_STATEFUL_DOMAINS= //.localhost
</code></pre>
<ol start="5">
<li>Verify if the routes are now available using <code>php artisan route:list</code> or <code>php artisan r:l</code>. This will list all available route for your application. Check if there are routes for <code>sanctum/csrf-cookie</code>, <code>login</code>, <code>register</code>, <code>forgot password</code>.</li>
<li>If routes do exist then you&#39;re done setting up your laravel api. That&#39;s all you need to have a working api authentication.</li>
</ol>
<p><strong>Connecting your React or any SPA</strong></p>
<p>You can now use react, vue or any SPA that you like. Now, when making a request using axios or any fetching library ensure to add the following configuration or any equivalent.</p>
<pre><code class="language-js">axios.defaults.withCredentials = true;
axios.defaults.withXSRFToken = true;
</code></pre>
<p>What this does is it will automatically handle the cookie whenever you send a request to your api application. Most likely if ever you use axios you&#39;ll have a setup like this.</p>
<pre><code class="language-js">import axios form &#39;axios&#39;;

export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
  withCredentials: true,
  withXSRFToken: true,
})
</code></pre>
<p>To begin authenticating a user, you can start by creating a basic login form. Before sending a POST request to the /login endpoint, you must first make a GET request to the sanctum/csrf-cookie route. Once the sanctum/csrf-cookie request is complete, you can proceed with authenticating the user via the /login endpoint. Typically, your auth functions would look like:</p>
<pre><code class="language-ts">// Make this request first then afterwards the login
const getCSRFToken = async () =&gt; {
	await api.get(&#39;sanctum/csrf-cookie&#39;, {
	  baseURL: import.meta.env.VITE_API_WEB_URL
	})
}

const login = async (form: UserLogin) =&gt; {
	const { status, data } = await api.post(&#39;login&#39;, form,
	  { baseURL: import.meta.env.VITE_API_WEB_URL }
	)
	// Handle the response
}

// Register Fn

// Logout
const logout = async () =&gt; {
	const { status } = await api.post(&#39;logout&#39;, null, {
	  baseURL: import.meta.env.VITE_API_WEB_URL
	})

	// Handle the logout
}
</code></pre>
<h3>Pre-flight</h3>
<p>You&#39;ll most likely see a preflight request before any api request you do this is automatically done by the browser. You can check more about it [here](A CORS preflight request is a <a href="https://developer.mozilla.org/en-US/docs/Glossary/CORS">CORS</a> request that checks to see if the CORS protocol is understood and a server is aware using specific methods and headers.)</p>
<p>You can cache for a certain amount of time so that preflight wont be sent for every request you make. Open the <code>cors.php</code> file in your laravel application and update the &#39;max_age&#39; configuration. Now whenever you make a request a preflight will be sent once only for every api endpoint and not for every request sent to the api endpoint.</p>
<blockquote>
<p>The preflight response can be optionally cached for the requests created in the same <a href="https://developer.mozilla.org/en-US/docs/Glossary/URL">URL</a> using <a href="https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Access-Control-Max-Age"><code>Access-Control-Max-Age</code></a> header like in the above example. To cache preflight responses, the browser uses a specific cache that is separate from the general HTTP cache that the browser manages. Preflight responses are never cached in the browser&#39;s general HTTP cache.</p>
</blockquote>
