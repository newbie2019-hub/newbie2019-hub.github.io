15:Tdd1,<h4>Basic Laravel Multi-tenancy</h4>
<p>Tenancy often concerned as team, domain or something more complex but the most basic definition of multi-tenancy is that it divides your data based on the user, account, etc.,</p>
<p>From <a href="https://tenancyforlaravel.com/docs/v3/introduction/">tenancy for laravel website</a></p>
<blockquote>
<p>What is multi-tenancy?</p>
</blockquote>
<blockquote>
<p>Multi-tenancy is the ability to provide your service to multiple users (tenants) from a single hosted instance of the application. This is contrasted with deploying the application separately for each user.</p>
<p>You may find this talk insightful: <a href="https://multitenantlaravel.com/">https://multitenantlaravel.com/</a>. Simply going through the slides will give you 80% of the value of the talk in under five minutes.</p>
<p>Note that if you just want to, say, scope todo tasks to the current user, there&#39;s no need to use a multi-tenancy package. Just use calls like <code>auth()-&gt;user()-&gt;tasks()</code>. This is the simplest form of multi-tenancy.</p>
</blockquote>
<p>Repeating condition of filtering by user id</p>
<pre><code class="language-php">public function index()
{
	$books = Book::where(&#39;user_id&#39;, auth()-&gt;id())-&gt;get();
	return response()-&gt;json($books);
}

public function store(BookRequest $request)
{
	$book = Book::create($request-&gt;validated() + [&#39;user_id&#39; =&gt; auth()-&gt;id()]);
	return response()-&gt;json($book);
}
</code></pre>
<p>Bind user ID for every query automatically and when creating the model also. This may be repeated for other model and to prevent repetition we can extract this to a trait and apply it to the model.</p>
<p>Note: There are also other ways that this can be achieved.</p>
<pre><code class="language-php">class Book extends Model {

	protected static function boot()
	{
		parent::boot();

		self::creating(function($model) {
			$model-&gt;user_id = auth()-&gt;id()
		});

		self::addGlobalScope(function(Builder $builder) {
			$builder-&gt;where(&#39;user_id&#39;, auth()-&gt;id());
		})
	}

}
</code></pre>
<p>Move the boot method to a trait so that it can be applied directly to the models that will need it.</p>
<pre><code class="language-php">use Illuminate\Database\Eloquent\Builder;

trait FilterByUser {

	protected static function boot()
	{
		parent::boot();

		self::creating(function($model) {
			$model-&gt;user_id = auth()-&gt;id()
		});

		self::addGlobalScope(function(Builder $builder) {
			$builder-&gt;where(&#39;user_id&#39;, auth()-&gt;id());
		})
	}

}
</code></pre>
<p>Book Model will now look like this.</p>
<pre><code class="language-php">use App\Traits\FilterByUser;

class Book extends Model {
	use FilterByUser;

	protected $fillable = [&#39;book&#39;, &#39;author&#39;, &#39;published_at&#39;];
}
</code></pre>
<p>The concept of multi-tenancy enables a single application instance to serve multiple users (tenants) while isolating their data securely. However, for simple scenarios like scoping resources to individual users, implementing a full multi-tenancy package is unnecessary. Instead, you can manage resource filtering by leveraging traits to minimize code repetition.</p>
<p>For developers requiring robust multi-tenancy solutions in Laravel, Here are <strong>some recommended packages:</strong></p>

<li><a href="https://spatie.be/docs/laravel-multitenancy/v4/introduction">Laravel Multi-tenancy</a></li>
</ol>
